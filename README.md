# Система управления базой данных магазина техники (CLI)

## Выбранная предметная область
Система для управления магазином техники. Включает 8 сущностей:
1. Роли (Roles)
2. Пользователи (Accounts)
3. Техника (Techniques)
4. Корзины (Carts)
5. Связь Корзины и Техники (CartTechniques - многие ко многим)
6. Адреса заказов (OrderAddresses)
7. Информация о заказе (OrderInformations)
8. Заказы (Orders)

## Что вынесено в каждый слой и почему
1. Domain (Доменный слой): Хранит модели данных (классы сущностей) и логику их сериализации/десериализации (toMap, fromMap). Они независимы от БД и консоли.
2. Data (Слой данных): Инкапсулирует работу с sqlite3. Содержит SQL-запросы для создания таблиц с внешними ключами (файл main_database.dart). Логика CRUD вынесена в отдельные классы в папке repositories (Паттерн Repository), чтобы не раздувать главный файл БД и соблюдать принцип единой ответственности (SRP).
3. CLI (Слой представления): Отвечает исключительно за взаимодействие с пользователем: вывод текста на экран и чтение ввода (через input_helper.dart), а также валидацию введенных данных перед передачей в репозитории.

## Какие валидации реализованы
Валидации реализованы внутри функций чтения ввода в файле input_helper.dart (или menu.dart):
1. Обязательное текстовое поле: Применяется .trim(), после чего проверяется, что строка не пустая (isNotEmpty).
2. Форматное числовое поле: Проверка, что введенная строка парсится в double и значение строго больше 0.
3. Форматное поле даты: Строка проверяется методом DateTime.parse(). Если формат неверный, программа выводит ошибку и просит ввести дату заново.

## Перечень тестов
Написаны тесты (test/main_test.dart) для проверки логики сериализации доменного слоя:
1. Role fromMap/toMap validation: проверка корректного маппинга сущности Role в словарь и обратно.
2. Account boolean parsing: проверка правильного преобразования типа bool (true/false) в int (1/0) для хранения в SQLite и обратного парсинга в bool при чтении из базы.
